## 摘要
基础分割模型擅长生成高质量、类别无关的掩码，但在将这些提议与特定目标对象关联方面存在困难。这一语义鸿沟严重阻碍了它们在机器人操作等下游应用中的部署，这些应用要求对未见过的对象进行精确分割。现有方法试图通过依赖详尽的3D对象模型先验来解决这一问题，这 inherently 引入了高昂的计算开销和复杂的多阶段流程。为应对这些限制，我们提出了SOS（用于无模型分割的流线型对象条件Transformer）。SOS完全消除了对3D模型的依赖，每个目标对象仅需一张参考图像。我们框架的核心是一种新颖的对象条件Transformer，它学习身份锚定查询，将掩码生成和目标识别统一到一次前向传播中。这种流线型设计显著提升了结构和计算效率。跨多个基准的广泛评估表明，SOS在无模型未见对象分割方面树立了新的最先进水平，提供了准确且高效的性能。项目页面和代码可在https://sos-seg.github.io/获取。

## Abstract
Foundation segmentation models excel at generating high-quality, class-agnostic masks, but they struggle to associate these proposals with specific target objects. This semantic gap severely hinders their deployment in downstream applications like robotic manipulation, which demand precise unseen objects segmentation. Existing approaches attempt to resolve this by relying on exhaustive 3D object model priors, inherently introducing prohibitive computational overhead and complex, multi-stage pipelines. To address these limitations, we propose SOS (Streamlined Object-conditional Transformer for model-free Segmentation). SOS completely eliminates the reliance on 3D models, requiring only a single reference image per target object. Central to our framework is a novel Object-Conditional Transformer that learns identity-anchored queries, unifying mask generation and target identification into a single feed-forward pass. This streamlined design drastically improves both structural and computational efficiency. Extensive evaluations across multiple benchmarks demonstrate that SOS establishes a new state-of-the-art for model-free unseen objects segmentation, delivering accurate and high-efficiency performance. The project page and code are available at https://sos-seg.github.io/.

### 研究动机与背景
- **基础分割模型的局限**：以SAM家族为代表的基础分割模型能够生成高质量、类别无关的掩码（mask），但这些模型无法将生成的掩码提议与场景中的特定目标对象进行关联，存在明显的“语义鸿沟”。
- **下游应用的需求**：在机器人操作、6D姿态估计等实际应用中，系统需要精确分割出**特定的未见对象实例**（unseen object instance），而不仅仅是生成类别无关的候选掩码。
- **现有方法的缺陷**：
  - **基于模型的两阶段方法**（如CNOS [32]、SAM6D [23]）：先使用SAM生成类别无关的掩码提议，再通过DINO等特征描述网络将提议与CAD模型渲染的模板进行匹配。这种“分割—匹配”分离的流程破坏了语义连贯性，且需要昂贵的3D CAD模型离线渲染阶段。
  - **基于模型的单阶段方法**（如OC-DiT [42]）：通过条件扩散模型直接预测掩码，但仍需大量CAD多视图渲染作为先验，且扩散模型的迭代去噪过程导致严重的推理延迟。
- **核心问题**：当前的未见对象分割方法对3D CAD模型先验的过度依赖，导致：
  1. 计算开销巨大（每对象需~18.82秒的模板渲染与特征提取）
  2. 流程复杂、多阶段管道松耦合
  3. 在现实“无模型”场景中难以快速部署
  4. 当仅提供单张参考视图时，这些方法性能急剧下降

### 论文提出的解决方案
SOS（Streamlined Object-conditional Transformer for model-free Segmentation）是一个**完全无模型**的统一单阶段框架，每个目标仅需**一张参考图像**，通过新颖的Object-Conditional Transformer学习身份锚定查询（Identity-Anchored Query），将掩码生成和目标身份识别统一到**单次前向传播**中。

## 2. 论文提出的方法论

### 核心思想
- **从“类别不可知提议+事后分类”转向“目标特定引用”**：传统DETR风格架构使用匿名查询（anonymous queries），需要先分割后分类；SOS则提出身份锚定查询，将条件参考的身份信息直接注入查询中，使查询成为目标身份的确定性描述符。
- **单参考视图即可提取身份先验**：借助大规模合成数据训练的模型，能够从一张参考图中提取足够的实例级判别特征，不再需要CAD模型的多视图渲染。

### 问题形式化
给定场景图像 \( I_s \in \mathbb{R}^{H \times W \times 3} \) 和 N 个对象条件 \( C = \{(C_i, M_{c,i})\}_{i=1}^{N} \)（每个条件包含参考图像和对应的前景掩码），模型预测一组二进制掩码 \( M = \{M_i\}_{i=1}^{N} \)。若目标不在场景中，则输出空掩码。

### 网络架构——三个核心组件

#### (1) 特征编码器（Feature Encoder）
- 使用**冻结的DINOv3-L/16**骨干网络提取语义特征
- **场景编码器**：场景特征图 \( F_s \in \mathbb{R}^{h \times w \times d} \) 展平为场景token，添加可学习的位置编码 \( P_s \)
- **条件编码器**：条件特征图 \( F_c \in \mathbb{R}^{N \times h' \times w' \times d} \) 展平为条件token，同时添加**空间位置编码** \( P_{c,patch} \)（保持参考视图内部布局）和**身份编码** \( P_{c,id} \)（区分不同条件）

#### (2) 对象条件Transformer（Object-Conditional Transformer）
- 初始化：复制一个可学习的通用语义探针 N 次，生成初始查询 \( Q \in \mathbb{R}^{N \times d} \)
- 每个block \( l \) 中，查询执行**双路更新**：
  1. **掩码交叉注意力**（Masked Cross-Attention）with 条件token \( T_{c,i} \) 和条件掩码 \( M_{c,i} \)：提取目标身份特征，防止条件间串扰
  2. **掩码交叉注意力** with 场景token \( T_s \)：由前一层注意力掩码 \( A^{(l-1)} \) 限制注意力范围，实现空间定位
  3. **自注意力**（Self-Attention）：查询间交换上下文信息，解决重叠目标和遮挡
  4. FFN处理得到精炼的身份锚定查询 \( \hat{Q}^{(l)} \)

#### (3) 掩码解码器（Mask Decoder）
- 每个block后通过轻量MLP和场景token的点积计算掩码logits：
  \[
  P^{(l)} = MLP(\hat{Q}^{(l)}) \otimes T_s
  \]
- 通过sigmoid和阈值二值化生成掩码预测 \( M^{(l)} \)，进而构造下一层的布尔注意力掩码 \( A^{(l)} \)
- 最后一个block的logits上采样到原始分辨率，sigmoid后阈值化输出最终掩码

### 训练目标
- 无需匈牙利匹配（查询与条件一一对应，天然与GT对齐）
- 采用Mask2Former风格的掩码损失：BCE + Dice损失
- 总损失：对第2、4、6、8层的输出进行**深度监督**

## 6. 论文的主要结论与发现

1. **显著优于单视图基线**：在单参考视图设置下，SOS达到平均AP 58.8，比最强的SAM6D（47.6）高出11.2个点。
2. **与CAD模型方法竞争**：尽管仅使用一张参考图，SOS的性能与使用42张CAD渲染模板的先进模型方法相当，甚至在LM-O（50.3 AP）和HB（65.6 AP）上超过了所有模型基线的SOTA。
3. **推理速度优势显著**：0.120秒/图，比CNOS快近2倍，比NIDS-Net和MUSE快4倍以上；且无需离线CAD渲染阶段（基线需额外~18.82秒/对象），实际部署总时间差距更大。
4. **身份锚定查询是核心创新**：用身份锚定查询替代匿名查询带来最大的性能提升（+18.4 AP），证明将身份信息注入查询设计是消除语义鸿沟的关键。
5. **双路注意力不可或缺**：场景交叉注意力和自注意力分别贡献15.8和6.2 AP，说明空间定位和查询间协作都至关重要。
6. **对称对象对参考视角不敏感，非对称对象敏感**：对称对象的AP波动仅1.1，而非对称对象波动达6.6；但整体平均AP的最大波动仅3.1，说明模型总体稳健。
7. **多视图可进一步提升性能**：将参考视图从1增加到3-4个可显著提升非对称对象性能，且SOS的缩放轨迹比基线更陡峭，用更少的视图达到更高性能。

## 7. 优点

### 方法上的亮点
- **彻底消除3D依赖**：仅需单张参考视图，无需CAD模型、模板渲染或外部区域提议网络，大幅降低部署门槛。
- **真正的单阶段统一架构**：掩码生成和身份识别在同一前向传播中完成，避免了“分割—匹配”分离导致的语义断裂。
- **身份锚定查询设计新颖**：从人类目标驱动搜索的认知效率获得灵感，将通用查询通过条件token和场景token的双路注意力逐步演化为确定性身份描述符，概念优雅且有效。
- **无需二分匹配**：查询与条件一一对应，简化了训练流程，避免了匈牙利匹配的复杂性。
- **支持负条件**：模型能处理目标不在场景中的情况，输出空掩码，增强实用性。
- **可扩展至多视图融合**：利用推理速度快的特点，无需复杂融合模块即可通过多视图推理进一步提升精度。

### 实验设计上的亮点
- 在4个多样化的BOP基准上评估，覆盖不同场景复杂度。
- 公平对比设计：与基线在相同参考图像、相同骨干网络条件下比较。
- 消融实验系统全面：分别验证了自注意力、场景交叉注意力、深度监督、查询设计等关键组件的贡献。
- 对视图条件敏感性进行了深入分析，并进行了分组（对称/非对称）讨论。

## 8. 不足与局限

### 论文自身指出的局限
- **无法处理多实例**：当前框架假设每个参考条件在查询图像中最多对应一个目标实例，无法处理同一查询图像中出现多个相同目标实例的情况。主要原因在于现有训练数据集缺乏多实例标注。

### 潜在不足与风险
- **没有对训练合成数据做详细分析**：模型的全部训练数据来自合成数据集（FoundationPose），论文未评估合成数据与真实数据之间的域 gap 对性能的具体影响。
- **零样本条件下的未见对象泛化有限**：虽然模型在BOP基准上表现优异，但这些对象类型可能与训练集中的Objaverse/GSO资产存在一定程度的重叠或相似性，“真正未见”的泛化能力尚未充分验证。
- **公平性细节不足**：对于基线方法在单视图适配的具体实现方式描述过于简略，读者难以完全判断比较的公平性——基线可能需要其模板集合的多样性来维持性能，单视图适配可能无法最大化其潜力。
- **深度监督的层选择缺乏消融**：仅报告了监督第2、4、6、8层与只监督最终层的对比，未探讨其他层的组合是否更优。
- **多视图融合策略简单**：仅通过IoU阈值和置信度筛选融合多视图结果，在目标遮挡严重或视图间预测差异大时，可能失效。
- **实际部署限制**：DINOv3-L/16骨干仍需要一定的GPU显存和计算资源，在嵌入式或低功耗机器人平台上部署仍有挑战。
- **评估指标限制**：仅使用AP指标，未报告如F1分数、边界质量（Boundary IoU）等其他分割质量指标，对分割边界的精细度评估不足。
